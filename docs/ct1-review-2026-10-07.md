## The two strategies currently running

1. **v11 paper bot** (`/opt/ct1/v11_paper_bot.py`, cron 9:31 and 15:55 ET). Three sleeves:
   ConnorsRSI mean reversion on SPY/QQQ (30%), 9-1 month sector momentum top-3 of 6 (25%),
   overnight AI basket (45%). The overnight sleeve was declared dead on Sep 25 after eight losing
   cycles (−$2,923) and is to be removed in v12. So in practice this is CRSI plus sector momentum.
2. **Wheel bot** (`/opt/ct1/wheel_bot.py`, cron 10:00 ET, separate Alpaca paper account). Sells
   5% OTM 30 DTE puts on the top-scored of 19 mega-cap/AI names, up to five names after the
   Oct 2 patch, closes at 50% of max profit after the Oct 6 patch.

The **SPY 0DTE iron condor** bot (Oct 3) is in DRY_RUN. Your own `trend_variants.csv` sweep over
102 sessions shows every 0DTE variant losing except "sell $5 spread vs trend 0.5% OTM, exit close"
at Sharpe 0.18 and +$362 total per contract. That is zero after slippage. Do not flip it live.

## What I found in the code

**v11**
- `is_rebal = day <= 7 and weekday < 5` rebalances the sector sleeve every weekday of the first
  week (fixed on droplet Sep 9). A one-line unit test would have caught it.
- `get_account()` returns a fake $100k equity when the API call fails, so a dead API sizes real orders
  on imaginary money. It should abort.
- State (`crsi_positions`, `sector_holdings`, `overnight_symbols`) is never reconciled against broker
  positions. The Sep 16 manual reconciliation was the symptom.
- `liquidate_symbol` sells the whole broker position, which destroyed sector holdings that overlapped
  the defensive overnight basket (fixed on droplet Sep 16).
- Signals come from yfinance, which changed its column format and broke the bot for days. Alpaca
  bars use the same keys the bot already has.
- Vol targeting is configured but not wired. Credit component uses a single day's log return of
  HYG/SHY, which is noise.
- No per-sleeve attribution from fills; the Sep 16 attribution was done by hand from 98 fills.

**Wheel**
- "IV" is 21-day realized vol × 1.2 and "IV rank" is realized-vol rank. The bot never looks at an
  implied vol. Alpaca's options snapshot endpoint returns real IV and greeks on the free feed.
- Strikes are a fixed 5% OTM regardless of vol: on NVDA that is near 35 delta, on JPM near 15 delta.
  Your own design doc specifies 10–15 delta.
- The covered-call leg is not implemented. After assignment the code logs "Have shares" and sets a
  flag. The wheel is half a wheel, and `phase == 'shares'` is never set anywhere.
- `get_option_chain` requests `limit=100` with no pagination. A 25–45 DTE window on a $200 stock
  has far more contracts than that, which is the "chain sometimes returns empty / no suitable puts"
  symptom.
- No earnings gate and no bear-score gate, both of which the design doc requires. Selling 30 DTE
  puts on NVDA through its earnings is the single largest risk in the book.
- After the Oct 2 patch: five names, up to 90% of equity in assignment notional, all correlated AI
  and mega-cap names. A 15% tech drawdown assigns four or five at once.
- Market orders on options pay the full spread (CRM example: 6.64 bid / 7.14 ask, 7%).
- `premium_collected` is never updated.

## How Claude Code strengthens these (versus Cowork)

Same model, but Code has a shell, a test runner, git, parallel workers, scheduled runs, and live
data adapters. Concretely:

1. **Put `/opt/ct1` under git.** Today the droplet is patched by string-replacement scripts with no
   history. With a repo, every change is a commit, the droplet does `git pull`, and I can read the
   real running code instead of a stale Drive copy.
2. **Tests before deploy.** `is_rebal`, sizing, the CRSI alignment fix, the double-buy guard, and
   the overnight-slice sell each become a five-line test that runs on every change.
3. **Broker reconciliation and fail-closed.** Every run starts from Alpaca positions and open
   orders; API failure aborts the run and emails you. No fake equity, no phantom positions.
4. **Real options data in the wheel.** I already have an Alpaca adapter that returns IV, delta,
   gamma, theta, OI and volume per contract (tested against recorded chains). Delta-based strikes,
   earnings and bear-score gates, the covered-call leg, chain pagination, and mid-price limit orders
   with a chase are a day of work with tests.
5. **Attribution from fills.** Tag every order with a `client_order_id` like `crsi:2026-10-07`;
   per-sleeve P&L then comes from the fills endpoint automatically.
6. **An external heartbeat.** The six-week blackout went undetected because nothing watched the
   watcher. A GitHub Actions job can ping the droplet's last-run file and email when it is stale.
7. **Real backtests on demand.** The CRSI table above took two minutes against six years of real
   data. The same harness can re-test v11 without the overnight sleeve, and v12 variants, before
   anything is deployed.

What Code cannot do from this cloud session: reach the droplet by SSH (the sandbox allows only
GitHub and PyPI), or see your desktop. The repo route solves both.
